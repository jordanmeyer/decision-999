# Synthetic browser fixtures

These are maintainer-authored fixtures, not evidence of an independent agent building an app or a student completing the workflow. Serve this directory through any existing loopback preview and open each tests page. No installation or framework is needed.

Pricing models `(price − unit cost) × quantity − fixed cost`. With 20, 12, 100, 500 the answer is 300; 500/8 gives 62.5 continuous units, so 63 whole units cover costs. At 62 units profit is −4; at 63 it is 4. A nonpositive margin with positive fixed cost has no break-even quantity. Amounts accept at most two decimal places; quantity is a whole number. Each input ranges from 0 to 1,000,000 inclusive. Integer cents keep intermediate arithmetic exact within this range; fractional cents are rejected rather than silently rounded. Price 19.90, cost 19.80, fixed cost 100, and quantity 1,000 give zero profit and exactly 1,000 break-even units. Fixed cost 100.01 genuinely requires 1,001 whole units. No fixed cost means zero units is a break-even point. The form applies the same precision and range limits as the model.

Inventory assumes independent days, with stock reset to the supplied amount each day. Demand is uniformly drawn from integer 0 through maxDemand using an explicitly seeded illustrative generator. Remaining stock is max(0, stock − demand); unmet demand is max(0, demand − stock). The accounting identity is stock + unmet = demand + remaining. No calibration, distribution-quality claim, or statistical accuracy result is implied.

For defect detection, copy the pricing fixture to scratch, change the profit formula to add 1, and open its tests page. Known-answer and boundary cases must fail. Restore the formula and reload to confirm the correction. Do not modify this preserved fixture to record a failed run.

The seeded expectation is derived independently with integer modular arithmetic: start state 42, update `(1664525 × state + 1013904223) mod 4294967296`, then calculate `floor(state × 21 / 4294967296)` for maximum demand 20. The first five states are 1083814273, 378494188, 2479403867, 955863294, and 1613448261; demands are 5, 1, 12, 4, and 7. At stock 10, remaining units are 5, 9, 0, 6, 3 and unmet units are 0, 0, 2, 0, 0. These constants were calculated separately using Python integer arithmetic, without importing or executing the application. This checks the specified generator and demand mapping; it does not validate randomness quality or a business demand model. A scratch mutation that makes every demand zero must fail this case.
