# Product and implementation decisions

The actual simulated student confirmed whole nonnegative batches,12boxes each, explicit minimum commitments, demand ceilings, fixed positive resource use and maximum contribution after variable costs. The app has no hidden fairness rule, customer preference, scheduling or uncertainty model. All inputs are synthetic. Quantities use modest0–100bounds; capacities0–10,000minutes; usage1–240minutes; contribution−$500…$500incentincrements. These classroom limits are visible and keep the problem interpretable.

Money is integer cents throughout generation/recomputation. LP objective coefficients are cents; UI formatting divides by100only for presentation. Resource use and quantities are whole integers for the recommendation. The solver's floating output is checked with1e-6quantity/resource tolerance and0.001cent accounting tolerance; whole quantities are rounded only after passing integrality checks, then resource use/objective are recomputed. Fractional LP values are displayed to four decimals and money to cents. Rounded display values are never used to establish feasibility.

HiGHS1.15.3 performs actual optimization in a dedicated ES worker, with Vite-bundled localWASM. Each request has a fresh worker; cancellation terminates it, and subsequent requests create a new one. The native solve limit is5seconds for each integer/LPsolve; main-thread total deadline15seconds includes loading. Revision checks discard outdated UI completions. Editing clears outputs and cancels activework. A fresh history return resets native controls with autocompleteoff; a persisted page preserves a completed coherent state, while an active solve is cancelled with an explicit notice.

An optimal integer answer is labeled proven optimal; a limited checked allocation is feasible without claiming optimality. Missing values never become zeros. Infeasible and unbounded statuses do not show allocations. Bounds make an unbounded UIcase impossible; a separate actual solver fixture tests that distinction. Limited-status branches are adapter tests, not fabricated timeout observations. In this positive-use/minimum-bound model, capacity below minimum required use is a quantified conflict; the UI does not pretend it proves a unique business cause or relax assumptions automatically.

The continuous LP relaxes only whole-batch policy and shares every other coefficient/bound. An optimal relaxation is an upper bound on the integer optimum. Its fractional values appear in their own section and are never the recommendation. Nearest-whole rounding is independently checked. Product upper/lower bounds and resource binding statuses are shown; there are no invented integer shadow prices. A manual mix is checked against solved assumptions with explicit infeasible arithmetic distinct from achievable improvement.

No chart library: native resource bars have a real exact semantic table alternative. Local Georgia/Arial and canonical designer tokens provide a calm navy/royal/copper operating worksheet without external fonts or institutional logos. Desktop and320px fixed frames are used because shared host viewport changes are prohibited. Clipboard fallback exposes selectable text ifpermissionunavailable; nothing is persisted or uploaded.

Simplification pass: keep only one model generation/verification path, one cancellable solver interface and native forms. No generic modeling language, state-management framework, saved scenarios, uploads, solver configuration UI or speculative abstraction. Controlled x0/x1/x2IDs prevent labels from becoming solver syntax. Only authored labels and numeric validated results enter HTML templates.
