# Core response to the example-app checklist

The October 9 review exposed recurring design habits and missing teaching requirements across the nine campaign apps. This patch changes Browser App Builder's shared stages, domain recipes and canonical Campus Designer resources. It also changes the gallery's framing and adds links to the actual planning/evaluation records. It does not revise the nine live applications or rewrite their historical evaluation results.

## Shared corrections

Plan retains the opening brief, requirement coverage and explicit deferrals; it records a learning objective, informative default and counterfactual. Build preserves that coverage and a consistent edit model, uses readable business copy/units and adds a compact worked-example route. Evaluate separately checks scope, first-load teaching behavior, arithmetic, rendered design and source applicability.

Conditional domain guidance preserves important distinctions: nominal process time versus sustainable capacity, unconstrained inventory benchmarks versus risk choices, dependency dates versus resource feasibility, integer capacity increments versus shadow prices, and a small hand-check dataset versus a substantial SQL exploration. It also covers dashboard evidence, market ranking causes, board-level presentation scope.

Campus Designer now ships licensed local EB Garamond/Open Sans files, with canonical generation into both starters. Its typography, component adapters and review guidance address actual font loading, lining/tabular figures, natural wrapping, control targets and decision-centered page density. Full model qualifications remain available; simplifying copy does not remove material limits.
