# Approval Studio — participant task

[Open the app](https://jordanmeyer.github.io/bab-example-process/). Reload or reset it before starting.

Allow 12 minutes. Start from the default app supplied by the facilitator. Think aloud; this reviews the app, not you. State predictions before changes or worked answers. You may use the app's guidance. Use the keyboard forms for this attempt; the facilitator will record any switch to pointer controls. Stop at the time limit and describe unfinished steps.

1. Explain the opening capacity and nominal-time results. Predict whether sending 10% rather than 30% of requests through Procurement fixes the capacity problem.
2. Apply that routing change while preserving the rest of the process. Explain the result. Deliberately leave the outgoing shares totaling 90%, apply them, explain the error and recover to a valid 100% total.
3. Restore the original example. Add a 10-minute Managers review named “Extra review” on the direct Manager approval → Finance route, with no entered wait. Connect it so 90% of requests go through Extra review and 10% through Procurement. Set Managers capacity to 680. Explain the resulting workload.
4. Reconnect Extra review back to Manager approval to create a loop. Explain which steps the error names and recover without restoring the original example. Export the valid process, restore the original example, and reimport your saved process. Explain what was restored and whether the comparison baseline traveled with it.
5. Name a decision this model cannot settle and one thing to investigate before recommending the routing in a real process.
